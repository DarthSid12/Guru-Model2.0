# Execution pipeline

Use this folder to change or run one part of the project without editing a dated experiment launcher. All paths default to locations relative to your working directory. Run commands from the repository root.

| Entry point | Purpose | Implementation folder |
|---|---|---|
| `download.py` | Fetch/import selected datasets | `components/downloads/` |
| `salience.py` | Compute fixation coordinates independently | `components/salience/` |
| `preprocess.py` | Normalize, pack, sample points and optionally render full fixation transforms | `components/preprocessing/` |
| `train.py` | Configure and launch checkpoint-compatible training | `components/model/` |
| `yin.py` | Noise calibration and configurable recognition experiments | `components/yin/` |
| `kanwisher.py` | Face target matching | `components/kanwisher/` |

`common/` owns configuration handling, provenance, file checks, model inference and transforms shared by multiple stages. `configs/` contains the visible defaults. The proven architecture, trainer and low-level transforms remain in the existing `training/` library so old checkpoints and scripts keep working. The execution files do not contain copies of that model code.

## Installation and controls

Python 3.12 was used for validation. Use an isolated environment:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r execution/requirements.txt
```

Select the PyTorch build appropriate to a GPU cluster in that cluster's environment. `--device` defaults to CPU for preparation/evaluation and `cuda:0` for training. GPU training must run on an allocated compute node.

Every file supports:

```bash
python execution/train.py --help
python execution/train.py --print-config
python execution/train.py --dry-run
python execution/train.py --config my_training.json --lr 0.0003
```

Precedence is built-in JSON defaults, then top-level keys in your `--config` file, then CLI overrides. Nested maps/lists are **replaced**, not merged; this lets you remove a category or model. Unknown top-level options fail. Primitive lists use space-separated CLI values. Dictionaries and lists of model records use JSON. Boolean flags support `--flag` and `--no-flag`. Relative paths are always relative to the working directory, not the config file.

New outputs must not already exist. An interrupted directory is retained for diagnosis. Choose a new output path rather than deleting prior artifacts. Training alone supports explicit `--resume auto` or `--resume /path/to/checkpoint_last.pth`.

Each stage records the resolved config and execution-module source hashes in `RUN.json`, or a timestamped `EXECUTION_*.json` for training. Successful stages write `COMPLETE.json` (download: `DOWNLOAD_COMPLETE.json`; training: the original trainer's checkpoint/summary files). New inference caches contain checkpoint and packed-data hashes. The existing historical caches retain their original receipts.

## 1. Download/import

Defaults select the **current** `faces_vgg2k`, `objects_wordbank64`, and `houses_synthetic128` training banks. These defaults preserve the current science rather than silently switching to the older public generic-house/ImageNet recipe.

The current face archive needs authorized access; the generated house views are our saved assets, not a public dataset download. Therefore default sources point to pre-split banks under `data/assets/`. Supply those files, an authorized archive URL, or a per-image source manifest. No credentials are built into the code and no synthetic views are regenerated by downloading.

```bash
python execution/download.py --datasets faces_vgg2k houses_synthetic128 --dry-run
python execution/download.py --config my_sources.json --output data/raw
```

A source entry can be one of:

```json
{
  "provider": "directory",
  "location": "/mounted/authorized/faces_vgg2k"
}
```

```json
{
  "provider": "archive",
  "location": "https://your-authorized-host/dataset.zip",
  "sha256": "the-expected-archive-sha256",
  "root_inside": "dataset"
}
```

```json
{
  "provider": "manifest",
  "location": "/path/to/photos.json"
}
```

An image manifest has `{"images": [{"split": "train", "class": "ball", "filename": "001.jpg", "url": "https://...", "sha256": "..."}]}`. Use `path` instead of `url` for a local image. Relative image paths resolve against the manifest directory. SHA-256 is optional for a new source, but should be supplied for reproducibility. All imported bytes get hashes in the completion receipt. Archives reject path traversal and links.

Source banks should already have the desired class selection and leakage-free splits:

```text
data/raw/<category>/train/<class>/<image>
data/raw/<category>/valid/<class>/<image>
data/raw/<category>/test/<class>/<image>
```

Downloading does not invent train/test splits or substitute generic house labels. For the exact current word choices, source manifests and synthetic-house split rules, see the root README and `handoff/DATA_AND_OPERATIONS.md`.

## 2. Full preprocessing

```bash
python execution/preprocess.py --raw-root data/raw --output data/packed
```

Default preprocessing resizes the short side and center-crops to 224 × 224 RGB, stores `images.npy`/`meta.json`, then computes 32 Gabor-salience points with 15% edge exclusion. Corrupt images fail instead of leaving silent empty rows. `--limit-per-class 10` is useful for a small check.

Packed output is compatible with the existing trainer:

```text
data/packed/<category>/<split>/images.npy  # uint8 [N,H,W,3]
                                  coords.npy  # int16 [N,K,2], (x,y)
                                  meta.json
```

Crop extraction, orientation, foveation and log-polar mapping normally run on the fly during training/inference. To inspect the **entire** deterministic preprocessing pipeline, optionally materialize these transforms:

```bash
python execution/preprocess.py --raw-root data/raw --output data/render-check \
  --categories houses_synthetic128 --splits valid --limit-per-class 1 \
  --render-fixations --render-variants lp cnn plain --render-orientations U I
```

This adds `fixations_<variant>_<orientation>.npy` in `[N,K,3,crop,crop]` format. LP means foveation + log-polar; CNN means foveation only; plain means neither. Inversion rotates each fixation crop 180°, matching the existing evaluation pipeline. Rendering can be very large, so it is off by default. Its outputs are for inspection/custom consumers; the standard trainer still reads images and coordinates. The standard trained architecture uses 180-pixel crops.

## 3. Change only salience

```bash
python execution/salience.py --packed-root data/packed --output data/new-points \
  --categories houses_synthetic128 --splits valid \
  --method gabor --num-points 32 --edge-margin 0.15
```

* `gabor`: sample proportional to Gabor orientation-variance salience, using the established implementation.
* `uniform`: sample Cartesian pixels uniformly without replacement.
* `grid`: use a deterministic near-square lattice.
* `--edge-margin 0.15`: exclude the outer 15% on each side. `0` permits the full image.
* `--attention-center '[0.5,0.5]'`: normalized `(x,y)` center of the Gabor attention prior. `null` preserves the original image-center behavior. This is separate from the edge-exclusion constraint.
* `--num-points`, `--seed`, `--batch-size`, and `--device` are explicit controls.

Gabor sampling is without replacement in its log-polar sampling map; rounding to Cartesian coordinates can still repeat a pixel. Uniform/grid sampling uses distinct Cartesian coordinates. The original image array can be hardlinked into the new output, but metadata and coordinates are newly written. Previous coordinates are never modified. Batch size, method, seed, and source images affect provenance; new packing is not claimed byte-identical to an older registered bank.

## 4. Training

```bash
python execution/train.py --dry-run
python execution/train.py --variant lp --output runs/lp_new
python execution/train.py --variant cnn --output runs/cnn_new --lr 0.0003
python execution/train.py --no-curriculum --epochs 30 --output runs/flat
```

Defaults match the current no-generic-house ResNet18 recipe: 124 epochs across 10 curriculum stages, AdamW LR 0.001, cosine schedule, weight decay 0.05, batch 256, 2,000 steps/epoch, 16 sampled fixations, seed46, and fixed class orders. `epochs` must equal the sum of `curriculum_epochs` when curriculum is enabled, so contradictory settings cannot silently pass.

Edit `curriculum_stages`, `curriculum_epochs`, `curriculum_pin` and `curriculum_image_caps` in a config to change the diet. Custom categories require corresponding stage/pin changes. Backbone, LP/CNN/plain variant, temperature, dropout, optimizer settings, augmentation, workers, AMP, early stopping, checkpoint frequency and resume are exposed in `--help`. Training invokes the established `training/train.py` and `training/model.py`; modify those library modules to change architecture or optimization internals.

## 5. Yin

### Current baseline

```bash
python execution/yin.py --cache-root /path/to/completed-sdsc/cache \
  --output results/yin_baseline
```

Default banks are CFD faces, DalHouses, and the fixed Wordbank object bank. Default designs are 20 faces + 20 houses and a separate 20 faces + 20 objects, with 12 within-category old/new pairs for each category. Sigma is 2, memory stores 10 fixations/image, tests use 32, and simulation seeds are 101–150. Noise is LP 0.373/CNN 0.364 in every study/test condition. The pinned cache registry checks exact known bytes.

```bash
python execution/yin.py --cache-root /path/to/cache --calibrate \
  --output results/yin_refit
```

Calibration happens once per model on `calibration_design` and `calibration_category` and transfers unchanged to all designs. Default anchor is face UU in the faces/houses design. `calibration_seeds`, `seeds`, targets and sigma are explicit. Calibration uses a bounded coarse/fine/ultrafine grid and reports out-of-range targets. The default fitting and reporting seeds overlap; these results are not independent validation. Use a disjoint seed set for independent evaluation.

### Noise rules

Pairs below are `(study noise, test noise)`. One parameter means p1 only.

| Protocol | UU | UI | IU | II | Fitted anchors |
|---|---|---|---|---|---|
| `single_uu` | p1,p1 | p1,p1 | p1,p1 | p1,p1 | UU |
| `study_only_fitted` | p1,p1 | p1,p1 | p2,p1 | p2,p1 | UU, II |
| `two_cross` | p1,p1 | p1,p2 | p2,p1 | p2,p2 | UU, II |
| `two_shared_ui` | p1,p1 | p1,p1 | p2,p1 | p2,p2 | UU, II |

For fixed two-noise experiments set each model's `noise` and `noise2` and leave `calibrate=false`. This includes the .28/.34 study-only diagnostic. Two-noise protocols require both values if not calibrating. Noise0 still samples Bernoulli codes.

### Composition and familiarity

Edit `designs` in a JSON config. Each category gives `pool`, `study`, `trials`; require `pool=study+trials`, `trials<=study`, and a large enough source bank. For example, a faces-only 40-study/24-test design uses `{"faces_only":{"faces":{"pool":64,"study":40,"trials":24}}}`. Selection and ordering are deterministic by design name and seed. Keep names unchanged for exact replay. Mixed memories interleave categories with no more than four consecutive items of one category; impossible compositions fail explicitly.

Readouts:

* `identity_max`: original KDE per stored image, then maximum across memories.
* `category_max`: maximum restricted to memories of the query's category.
* `pooled_category`: one KDE over all stored fixations in that category.
* `pooled_all`: one KDE over every stored fixation.

Category-restricted methods assume the category is known. No test images enter the stored memory. Scores retain the original `1e-12` floor and strict comparison; ties count incorrect. Raw counts and accuracy %, mean ± sample SD/SEM, are saved. Test pairs always compare within a category.

### New checkpoints

Set `models[].run_dir` to a directory containing `config.json`, `label_map.json`, and `checkpoint_last.pth`. Supply compatible packed evaluation banks with a `valid` split, a new `cache_root`, and `verify_registry=false`. The shared feature builder loads the checkpoint strictly, creates deterministic upright/inverted sigmoid caches, and records hashes. Set `calibrate=true` for a new model rather than blindly reusing the historical noise rates. Model cache subdirectories must be distinct.

## 6. Kanwisher

```bash
python execution/kanwisher.py --cache-root /path/to/setA/cache \
  --packed-root /path/to/setA/packed --output results/kanwisher
```

Defaults: original Set A bank (`faces_setA`), 40 identities × 5 photographs, 16 fixations, seeds101–150. One per-model noise is fitted to 87.5% upright accuracy on seed42 and held for inverted. Averaged binary fixation codes use Pearson correlation distance. All 156,000 ordered target/match/distractor triplets per orientation are evaluated; strict ties count incorrect.

Set a model's `noise` to a number to skip fitting. New checkpoints use the same shared inference builder as Yin. Counts must exactly match the supplied bank; the runner does not silently pick arbitrary faces. Existing old-style `U.npy`/`I.npy` caches work with the corresponding packed `meta.json`. Newly built caches carry identity metadata themselves.

## Validation and branch preservation

Run focused tests:

```bash
python -m unittest discover -s execution/tests -v
```

This implementation was checked with:

* All six CLI defaults and the actual training argument parser.
* A tiny source-import → preprocessing → one CPU optimizer step → new checkpoint inference → Yin/Kanwisher smoke run.
* Standalone uniform and Gabor coordinate generation and optional full fixation rendering.
* Full 50-seed Yin replay with refitted noise: all 1,600 category records match the prior results exactly.
* Full Set A Kanwisher replay: all 200 model/orientation/seed rows match the prior exact correct/trial counts and noise fits.

The older root test suite passed six tests on this Mac; its existing Linux `/proc` process-token test failed because macOS has no `/proc`. That historical queue code and test were not changed. The eight modular contract tests passed.

These checks are code verification, not new production training or new scientific claims. Existing registered sources/data and cluster jobs were not changed. Historical sources remain available in the handoff branch and snapshots.

[Branch cleanup receipt](BRANCH_CLEANUP.json) records three deleted redundant personal branches and their recoverable archive tags. Branches containing unique `ddeightmore` work were preserved.
